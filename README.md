# 字帖生成器

给 5 岁小朋友生成大字米字格字帖，输出矢量 PDF。

现有在线字帖网站的字普遍偏小（多用固定尺寸的模板位图，或按固定 px 渲染字体，放大就糊）。
这里走矢量路线：汉字是**笔画轮廓路径**，格子大小是自由参数，打印任何尺寸都锐利。

线上：**https://walkerwalker.github.io/zitie/**

## 跑起来

```bash
npm install
npm run dev          # http://localhost:5173
```

不经浏览器直接出一份 PDF（用来检查笔画落位）：

```bash
npm run smoke                                              # 默认 大水 → /tmp/zitie-smoke.pdf
npm run smoke -- 水 /tmp/a.pdf '{"cols":4,"gridType":"tian"}'
```

## 一页长什么样

**一页所有格子一样大。**唯一的排版参数是**每行几格**：
格子边长 = 可用宽度 ÷ 列数，所以横向永远正好铺满一整页；纵向能塞几行是几行，余数上下平分。
选「几格」比拖毫米好决定 —— 一共就六个选项，每一个都是一张能直接印的纸，不用在 47 和 48mm 之间纠结。
默认每行 5 格 → 37.6mm 米字格，A4 上 5 × 7 = 35 格。
下面这张示意图用每行 3 格（3 × 4 = 12 格）画，紧凑一点，规则是一样的 —— 拿 4 笔的「水」举例：

```
┌──────┬──────┬──────┐
│  ●   │  1   │  2   │  ● 全黑范字（照着看，不用描）
├──────┼──────┼──────┤
│  3   │  4   │  全  │  n 写到第 n 笔的样子，整格浅灰
├──────┼──────┼──────┤
│  全  │  全  │      │  全 笔顺排完，再印 3 个整字，同一个灰
├──────┼──────┼──────┤
│      │      │      │    剩下的全是空格，自己写
└──────┴──────┴──────┘
```

**整页只有一条规则：浅灰的就描，黑的不用动。**
第一格是全黑范字，之后每一格是「写到第 i 笔的样子」，**整个字都是浅灰的** ——
每一格都是完整的一次描写练习，而不是只描新增的那一笔。
笔顺格和练习格没有区别：一样大、一个灰，逐笔累加本身就是主要的练习内容。

绕了三圈才到这儿，前两次都栽在分解格的黑灰语义上：
先是旧笔画浅灰、新笔画黑（小朋友会去描一堆旧笔画，旁边还多一条不知道干嘛的黑线），
改成旧黑新浅灰仍然别扭 —— 一格里黑灰混着，眼睛不知道该看哪。
第三次是把笔顺缩成一条小格子的「附注条」，也错了：**逐笔分解才是主角，格子不能小**。
现在没有多余的画法可选了，只有一个灰、一种尺寸。

**整字固定 3 个，不跟着页面大小变。**描完就该自己写了，多描没意义 ——
所以格子调小之后多出来的空间全给空格，而不是印一版两百个一模一样的字。

## 一页放几个字

格子调小之后一页能塞 70、88 格，一个字撑不满，空得太厉害。所以**一页上下两半，一半一个字**：

- 半页 = `floor(行数 / 2)` 行，行数是奇数时多出来的那行给下半页（上半少、下半多）。
- 一个字占半页的条件：**这个字的全部格子 + 至少一整行空的**，装得下才放。挤不下就独占一整页。
- 半页矮到只有 3 行就干脆不切了 —— 笔顺排完剩不下几格空的，还不如整页给一个字。
  所以每行 **6 / 7 / 8 格**（半页 4 / 5 / 5 行）一页两个字，**3 / 4 / 5 格**一页一个字。
- 字数是奇数时，最后一个字自己占上半页，下半页全是空格 —— 和整页给它一个字是一样的纸。

| 每行 | 格/页 | 半页 | 一页几个字 |
|---|---|---|---|
| 3 | 3×4 = 12 | 2 行，太矮 | 1 |
| 4 | 4×5 = 20 | 2 行，太矮 | 1 |
| 5 | 5×7 = 35 | 3 行，太矮 | 1（默认，维持原样） |
| 6 | 6×8 = 48 | 4 行 = 24 格 | 2（≤14 笔） |
| 7 | 7×10 = 70 | 5 行 = 35 格 | 2（≤24 笔） |
| 8 | 8×11 = 88 | 5 / 6 行 | 2（≤28 笔） |

**没做成选项**：界面上已经只剩一个旋钮了，再加一个「一页两个字」的勾就白搭 ——
而且真正的使用者（奶奶）不该再多面对一个选择。要改就是 `layout.ts` 里 `MIN_BAND_ROWS` 一个常量：
调成 3，每行 5 格也会一页两个字。

分页：一个字的格子序列 = 1 个范字 + 每笔一格 + 3 个整字。
半页装不下就整页，整页还装不下才真的翻页 ——
每行 3 格 = 12 格/页时蠢（21 笔）要三页，后面几页接着排剩下的笔顺和整字。
一个字跨页时预览和页脚标成 `蠢 1/3`。

代价：一页两个字的时候，如果前一个字占了上半页、下一个字笔画太多只能独占整页，
上半页那一半就空着过去了（不重排字序 —— 顺序是用户输入的顺序）。少见，能接受。

## 数据与输出

- **笔画数据**：[`hanzi-writer-data`](https://www.npmjs.com/package/hanzi-writer-data) 2.0.1，源自 Make Me a Hanzi。
  9574 个字（简繁都有），每字一个 JSON，含每一笔独立的 SVG path 和中线（medians，暂未使用）。
  坐标系 1024 见方、y 轴向上，字身盒子 `(0, -124)` → `(1024, 900)`；路径只用到 `M L Q C Z` 全绝对坐标。
- **按需加载**：dev server 有个中间件（`vite.config.ts`）直接从 `node_modules` 喂 JSON，
  32MB 不进打包产物。生产构建下 `strokeData.ts` 自动回落到 jsDelivr CDN。
- **PDF**：`pdf-lib`，全矢量，**完全不嵌入中文字体**（字是路径不是文字，省体积也绕开字体授权）。
  `drawSvgPath` 做的是 `translate(x,y) → scale(s,-s)`，所以传 `{x: 0, y: 页高, scale: mm→pt}`
  就能让「毫米、y 轴向下、原点页面左上」的路径直接落位。

## 结构

一次几何计算，两个后端渲染，保证预览和 PDF 一致：

```
src/layout.ts         排版核心：格子布局、分页、生成绘图图元 Prim[]（毫米 / y 向下 / 原点左上）
src/pathTransform.ts  笔画 path 的仿射变换，字身盒子 → 格子
src/strokeData.ts     笔画数据拉取 + 缓存（本地 → CDN 回落）
src/renderSvg.ts      Prim[] → SVG 字符串（页面预览）
src/renderPdf.ts      Prim[] → PDF（pdf-lib）
src/main.ts           控制面板 + 预览，配置存 localStorage
scripts/smoke.ts      Node 侧烟测
```

## 可调项

界面上**只有一排按钮：每行 3 / 4 / 5 / 6 / 7 / 8 格**（62.7 / 47.0 / 37.6 / 31.3 / 26.9 / 23.5mm），默认 5。
这本来就是做这个网站的理由，其余全部定死：

| 定死的值 | | 为什么不做成选项 |
|---|---|---|
| 格子大小 | 算出来的 | 可用宽度 ÷ 列数，不再是能拖的旋钮 |
| 页边距 | 左右 11mm | 上下是余数平分，所以比 11mm 大一点 |
| 字占格子 | 72% | 再大就顶格，小朋友没有起笔的余地 |
| 格型 | 米字格 | 斜线和十字线一个灰度，加上去也没盖过字 |
| 格线颜色 | 灰 | |
| 整字个数 | 3 个 | 描完就该自己写了，剩下的格子全留空 |
| 描红灰度 | 0.82 | **淡到刚好看得见就行 —— 人要拿笔写上去的** |
| 格线灰度 | 0.74 / 线宽 0.25 | 比描红的 0.82 还深一档，但虚线细又断，看上去仍退在字后面 |

这些值还留在 `Config` 里，是为了烟测能覆盖：`npm run smoke -- 大 /tmp/a.pdf '{"gridType":"tian"}'`。

整页的层次是：**黑范字 > 浅灰的字 > 格子虚线** —— 比的是视觉分量，不是 RGB。
格线一开始按 RGB 排（0.88，比描红更淡），结果米字格淡到看不见，改成 0.74 + 线宽 0.25。
另有一层容易忘：`gridPrims` 里的 `k = cell / 50` 会按格子大小缩线宽和虚线，
默认的 37.6mm 格子上 k = 0.75，所以上面那些值实际都要再打个七五折 ——
「太浅」这个反馈就是这么来的：0.88 是当年默认 50mm 格子时调的，换成 5 格之后又被缩了 25%。

一路砍掉的选项：描红行数、描红逐行变淡、笔顺条画法（五种）、尽量压到一页、格型、格线颜色、
页边距、字占格子、末尾留空行数。整页只有一个灰、一种格子，这些旋钮就都没有意义了。
最后连「格子大小」自己也砍了 —— 毫米是连续的，选起来没有着落点，
而且左右总要剩一条边；换成选列数，格子大小是算出来的，横向必然铺满。

## 状态

MVP 已跑通：输入汉字 → 实时 SVG 预览 → 下载矢量 PDF。

已验证：每行 3–8 格全部六档（3×4=12 到 8×11=88 格/页），田字格 / 米字格 / 方格，灰红绿三种格线，
1–21 笔的字，一页两个字（6 / 7 / 8 格）与一页一个字（3 / 4 / 5 格）两种分块，
字数为奇数时最后一页只占上半页，笔画多的字退回整页（大蠢水 @ 6 格 → 三页各一个字），
跨页排版（蠢 21 笔 → 每行 3 格时 3 页，标成 `蠢 1/3`），
字库缺字提示（龘），标点与重复字过滤。

一个已知的边界：**整页**那条路上，格子序列正好铺满一页时一个空格都没有
（每行 3 格 = 12 格，而 8 笔的字正好 1 + 8 + 3 = 12）。要不要强行留一行空（代价是多翻一页）还没定。
半页那条路上不存在这个问题 —— 「至少留一整行空的」本来就是占半页的条件。

想过但按 MVP 范围**没做**的：拼音标注、基础笔画练习页（横竖撇点折）、空心字描红、
数字 0-9 页、内置生字表、粘贴整段课文提取。

## 部署

GitHub Pages，`gh-pages` 分支存构建产物（`main` 只放源码，`dist/` 已 gitignore）：

```bash
npm run build
cd dist && git init -b gh-pages && git add -A && git commit -m build
git push -f https://github.com/WalkerWalker/zitie.git HEAD:gh-pages
```

`vite.config.ts` 里 `base` 只在 `command === 'build'` 时是 `/zitie/`，本地 dev 保持 `/`。
`dist/.nojekyll` 是给 Pages 用的，不然 Jekyll 会吞掉下划线开头的文件。

线上没有 dev server 那个中间件，`/hanzi/*.json` 一律 404，
`strokeData.ts` 每个字先白跑一次再回落到 jsDelivr —— 能用，但每个字多一个来回。
真要省这一跳，就是在 `fetchChar` 里用 `import.meta.env.DEV` 跳过本地那条路径。

**待验证**：微信内置浏览器里能不能下载 PDF。已知微信屏蔽文件下载，
iOS 顶多预览、且预览页不能「作为文件转发给朋友」，
所以大概率要改成「把每页渲染成图片，长按发送给朋友」。
